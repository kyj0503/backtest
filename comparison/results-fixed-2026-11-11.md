# Python / Rust 동작 수정 및 재측정 — 2026-11-11

환율 날짜와 확인된 입력·응답 차이를 수정했다. 동일 OHLC·환율을 고정한 실데이터 계산 32개는 모든 비교 필드가 허용 오차 안에서 일치했다. 정상 HTTP 시나리오 37개 모두 성공했고, 성과 지표 차이는 없었다. 경계 입력 35개도 HTTP 상태와 응답 비교를 통과했다.

완전한 바이트 동일성을 뜻하지 않는다. 숫자는 `max(1e-6, abs(expected)*1e-6)` 오차를 허용하며 실행 시각·소요 시간 등 메타데이터는 제외한다. 실제 Yahoo 재조회가 있는 일본·유럽 사례에는 아래에 명시한 미세한 입력 시세 차이가 남는다.

## 수정 내용

- Yahoo 봉의 날짜를 현재 UTC 오프셋 대신 **해당 날짜의 IANA 시간대 규칙**으로 해석한다. 영국 환율의 여름·겨울 전환을 회귀 테스트에 포함했다. UTC 조회 범위를 넓혀 첫날 누락을 막고, 반환하는 날짜는 요청한 시작일~종료일로 제한한다.
- 이전 방식으로 저장한 환율 캐시는 버전 표식을 확인해 거부하고, 해당 환율 종목만 트랜잭션으로 다시 저장한다. 중간 저장 실패 시 기존 행과 표식이 함께 롤백된다. 스키마 변경이나 DB 볼륨 초기화는 없다.
- Python처럼 Yahoo 시세 저장 후 DB의 DECIMAL 정밀도로 다시 읽는다. 최초 조회와 캐시 조회의 계산 정밀도가 달랐던 경로를 수정했다.
- DCA 일별 평가액의 정규화·복원 순서를 Python과 맞췄다. 0에 가까운 일간 수익률의 부호 때문에 상승일·하락일·승률이 달랐던 사례를 해결했다.
- 숫자 문자열·불리언 투자금, 명시적인 null 리밸런싱, 중복 조회 파라미터의 마지막 값 사용, 검증 오류의 `detail` 배열과 필드·문구를 맞췄다. 잘못된 HTTP 메서드도 Python과 같은 JSON 405를 반환한다.
- 상장일은 Python처럼 **조회 전에 DB에 이미 있는 메타데이터**로 검사한다. 메타데이터가 없던 첫 요청은 최초 제공 봉부터 계산할 수 있고, 상장일이 저장된 뒤에는 상장 전 시작일을 거부한다. 수정 전 시험에서 Python의 첫 요청만 관찰하여 이 상태 의존성을 놓쳤던 점도 바로잡았다.
- 티커 정보, 부분 실패 경고, 현금 우선·종목 입력 순서의 결과 목록, ISO 보유기간, `Entry_*`/`Exit_*` 지표 진단 컬럼을 맞췄다. `asset_type`이 없는 실제 주식 티커 `CASH`는 결과에 한 번만 나온다.
- 같은 클라이언트의 동시 실행 상한 오류 문구와 `Retry-After: 10`을 맞췄다.

조회 생략 시 `ticker_info.currency`의 USD 기본값도 기존 응답 계약을 따른다. 실제 평가 계산에는 확인한 원래 통화와 환율을 사용하며, 별도 `/prices` 응답에는 원래 통화가 나온다.

## 검증과 데이터 출처

- Docker test target: fmt, clippy 경고 0, API·데이터·취소 등 14개 테스트, 64개 기존 Python 기준 계산 사례와 실데이터 6개 추가 사례 통과. 64개 사례의 결과 목록 및 전체 거래 로그 필드까지 비교를 확대했다.
- 입력 오류 23개는 수정 전 Python HTTP 응답을 그대로 기준 파일로 보존했다. Rust 출력으로 기대값을 만들지 않았다.
- 별도 임시 MySQL에서 저장·조회·실패 롤백·구버전 환율 캐시 복구·상장일 사전 검사 통과. 테스트용 DB는 제거했다.
- cargo-audit: 240개 의존성, 예외 없이 통과. Rust runtime 이미지 빌드 통과.
- 원래 Python 시세 스냅샷과 원래 Python 엔진 결과를 사용한 32개 실데이터 재실행에서 차이 0개. 일별 평가액의 최대 절대 차이는 **8.731149137020111e-10 USD**다. 손익·거래 로그·일별 수익률·DCA 일수 등 비교 필드가 모두 허용 오차 안이다.

재현 자료는 `.comparison/reports/scenarios-fixed/replay-{python,both,summary}.json`에 있다. 회귀 기준은 `backtest_be_rust/tests/fixtures/{parity,real-market-python,http-boundary}.json`이다.

## 실행 조건

- 최종 HTTP 결과: `.comparison/reports/scenarios-final/`. 정상 37개에 최초 호출 1회 + 반복 5회, 경계 35개, 동시 요청 16개 묶음. 전체 응답을 읽는 시간이며 클라이언트 JSON 해석 시간은 제외한다.
- API별 CPU 2개·메모리 2 GiB·서버 프로세스 1개. 프론트엔드 2개와 DB 2개도 계속 실행 중이다. 성능 측정과 메모리 관측은 순차 실행했고 빌드·브라우저 시험을 겹치지 않았다.
- Python 이미지: `sha256:6f622a697e0b65e197cdd7959f7e6f913a80ba25d2c4b7b6d5f622f774837c3c`.
- 최종 Rust 이미지: `sha256:bda62be9e3bcf9629170634bf5ada176124085ba589d7f363285f2e08c07edd1`.
- 비교의 입력을 맞추기 위해 Python DB의 공개 시세 17종을 Rust 비교 DB로 한 번 복사했다. Python DB는 수정하지 않았다. Rust의 기존 시세와 메타데이터 백업, 원본 해시는 `.comparison/reports/scenarios-fixed/cache-alignment/`에 보존했다. 사용한 도구는 [align-local-price-cache.py](align-local-price-cache.py)이며 로컬 비교 DB 주소로 고정되어 있다.
- 합성 시세나 고정 응답 서버를 사용하지 않았다. 각 서비스는 여전히 자체 DB와 Yahoo를 사용한다. API 메모리 캐시는 재시작으로 비웠지만 DB·호스트 파일 캐시는 유지했으므로 최초 호출도 완전한 콜드 스타트 수치가 아니다.
- 수정 전 수치는 [원래 성능 보고서](results-2026-11-11.md)와 [원래 메모리 보고서](memory-results-2026-11-11.md)에 보존했다. 서로 다른 시간의 실행이므로 수정 전후 시간 차이를 코드 변경만의 영향으로 단정하지 않는다.

## 동작 비교 결과

삼성전자 SMA(2023-01-03~2023-10-31, 원금 $10,000)는 수정 전 Rust가 **+1.613219% / $10,161.321922**였지만, 수정 후 **−2.071531% / $9,792.846910**으로 Python과 일치했다. 일별 평가액 차이는 최대 **5.46e-12 USD**, 거래 5건도 일치한다.

정상 37개 중 36개는 전체 비교 필드가 허용 오차 안이다. 일본·유럽 조합은 주요 성과 지표는 일치하지만 일별 수익률 등 일부 필드에 미세한 차이가 있다. 일본의 시작일 휴장으로 두 구현이 Yahoo를 다시 조회하면서 조정 주가의 일부 값이 달라진다. 마지막 DB 스냅샷에서도 차이는 `7203.T`에만 있었고 종가 최대 차이는 0.0007 JPY였다. 동일 가격을 고정한 이 사례는 차이가 없다. 외부 시세를 각각 다시 받는 모든 미래 요청까지 비트 단위 동일함을 보장하지 않는다.

경계 35개는 성공 응답과 오류 응답을 모두 비교해 차이가 없다. 상장일 메타데이터가 이미 저장된 RIVN은 양쪽 모두 같은 422를 반환한다. 정상 37개 × 6회 × 2개 구현, 경계 35개 × 2개 구현을 모두 실행했다.

같은 클라이언트의 8개·16개 동시 요청은 양쪽 모두 2개 성공, 나머지는 같은 429 본문과 `Retry-After: 10`이었다. 서로 다른 클라이언트 16개 요청은 양쪽 모두 성공했다. 이는 단일 묶음 시험이며 장시간 처리량·메모리 누수 시험은 아니다.

뉴스는 인증값이 없어 빈 결과 경로만 검증했다. 운영 Turnstile 성공 토큰, OCI DB TLS, ARM64 실행 및 모든 운영 관측 지표의 동일성은 이번 재검증 범위에 포함하지 않았다. 커밋·푸시·운영 배포는 하지 않았다.

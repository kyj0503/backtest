# S01~S06 수정·독립 정확성 재검증

검증일: 2026-11-11. 백엔드·프론트엔드 브랜치: `rust-migration`.

[3차 적대적 평가](rust-third-adversarial-audit-2026-11-11.md)의 S01~S06을 모두 수정하고, 최종 소스의 Docker 검사·HTTP·브라우저 검증과 성능/메모리 재측정을 완료했다. 정확성 판정은 독립적인 현금·수량·수수료 산식, 날짜, 통화, 복리 수익률이다. Python 구현은 성능 비교 대상으로만 사용했다.

수량 모형은 **수정주가 기반 소수 단위의 총수익 모형**이다. 당시 실제 정수 주식 수, 최소 매매 단위, 실물 배당 현금 흐름을 재현하는 모형으로 해석하면 안 된다. 예전 정수 수량을 기대하던 회귀 네 곳은 출력값 복사가 아닌 새 모형의 독립 원장 산식으로 갱신했다. Python parity fixture는 변경하지 않았다.

`EntryPrice`/`ExitPrice`는 기존 USD 원장 가격을 유지한다. `EntryPriceNative`/`ExitPriceNative`는 체결일의 유효 FX로 환산한 종목 통화 가격이며 주가 차트에서 사용한다. 네이티브 가격이 없고 원장 통화가 차트와 다르면 잘못된 통화 가격을 그리지 않는다. 비중은 **각 종목 계정의 보유자산+매수 대기 현금**이다.

브라우저 검사 중 숫자 시간축을 적용한 기본 Recharts 툴팁이 시간 값과 종가를 표시하는 문제가 드러나 실제 체결 정보를 그리는 툴팁으로 수정했다. 최종 테스트와 이미지들은 이 수정까지 포함한다.

## 성능과 메모리

원본 입력 `.comparison/reports/corrected-2026-11-11/benchmark-inputs`를 그대로 사용했다. CPU 2개·메모리 2GiB, 새 API 프로세스에서 32개 시나리오를 각 10회 실행하고 동시 2/8/16 요청을 추가했다. 이번 Python/Rust 각각 346건, **692건 모두 HTTP 200**, OOM·swap 0이다. 중앙값·p95는 순차 320건의 통합 분포이며 p95는 nearest-rank다.

| 구현 | 응답 중앙값 | p95 | 유휴 cgroup 메모리 | 커널 최대 메모리 |
|---|---:|---:|---:|---:|
| 이전 Rust (Yahoo 교체 직후 측정) | 3.84 ms | 7.68 ms | 3.38 MiB | 68.56 MiB |
| 수정 Rust (이번 측정) | 4.28 ms | 8.15 ms | 4.11 MiB | 70.73 MiB |
| Python (이번 재측정) | 97.84 ms | 259.11 ms | 153.48 MiB | 220.81 MiB |

이번 Rust는 이번 Python보다 중앙값 기준 **22.8배 빠르고**, 최대 메모리는 **68.0% 적다**. 이전 Rust 측정 대비 중앙값은 **11.6% 증가**, 최대 메모리는 **3.2% 증가**했다. 이전 값은 이번에 다시 실행한 대조군이 아니라 같은 날 보존된 직전 측정이다. 시행 간 변동을 포함하므로 전부 코드 변경의 인과 효과라고 단정하지 않는다.

예시: 5종목·8년 순차 중앙값은 Rust 8.61ms / Python 259.29ms, 동시 16요청 중앙값은 Rust 34.95ms / Python 4,176.79ms다. 전체 요청의 단순 중앙값은 시나리오 구성을 반영하므로 개별 사용 패턴의 보장값이 아니다.

관측기는 별도 cgroup에서 API를 관찰한다. 최대값은 `memory.peak`의 컨테이너 전체 수명 최대이고, 시나리오별 1ms 요청 주기의 관측 최대는 샘플링 하한이다. Rust RSS high-water는 74.32MiB, Python은 256.61MiB이며 cgroup 메모리와 다른 지표다. **외부 Yahoo/DB 조회 및 브라우저 메모리를 제외한 고정 시세 API 벤치마크**다. 빌드·브라우저 검사를 종료한 뒤 측정했다.

# Yahoo 수집 라이브러리 전환 및 회귀·성능·메모리 검증

검증일: 2026-11-11 (한국 시간). 브랜치: 백엔드·콘솔 모두 `rust-migration`.

Rust의 Yahoo Chart 직접 HTTP 호출을 `yahoo_finance_api 5.0.0`으로 교체하고 로컬 Rust API 이미지를 업데이트했다. 날짜·수정주가·환율 회귀와 실제 Yahoo 조회를 검증했으며, 교체 직전/직후 이미지를 동일 시세로 다시 측정했다. 계산 검증의 기준은 독립적인 날짜·원장 산술이다. 원본 Python의 계산 결과 일치를 정확성 근거로 삼지 않았다.

기계 판독 결과: [yahoo-client-evidence-2026-11-11.json](../../comparison/yahoo-client-evidence-2026-11-11.json).

## 구현 변경

- `DataSource`가 공유 `Arc<YahooConnector>`를 보유하고 `get_quote_history()`로 일봉을 가져온다. 날짜를 UTC 경계로 변환하고 시작 −1일/종료 +2일 패딩을 유지한다. 최종 결과는 요청한 거래소 날짜 범위로 제한한다.
- `governor` 기능을 활성화했다. 라이브러리 기본 10 requests/second limiter를 `DataSource` 복제본들이 공유한다. 이는 Yahoo가 보장하는 허용량이라는 뜻은 아니다.
- `reqwest`를 0.12.28에서 0.13.5로 통일해 HTTP 클라이언트 버전 중복을 피했다. 뉴스의 query, Turnstile의 form, JSON, Rustls 기능을 명시했다. 기존 잠금 패키지 중 버전이 바뀐 것은 reqwest이며, 라이브러리와 관련 의존성이 추가되어 외부 잠금 항목은 239→306개다. OS·플랫폼·개발용 항목도 포함한 수다.
- 연결 5초/HTTP 요청 15초 제한과 공유 클라이언트를 유지하고 Yahoo 작업 전체에는 45초 상한을 둔다. 라이브러리가 HTML·빈 본문·5xx를 한 번 재시도하며 앱은 네트워크 오류만 최대 세 번 시도한다. 429·인증·파싱 실패는 데이터 없음으로 숨기지 않고 503으로 반환한다. 404/실제 빈 시세는 별도로 처리한다.
- 현재 사용하는 Chart 메서드는 쿠키/crumb를 요구하지 않는 경로다. 다른 메서드의 인증 갱신 기능을 이 일봉 요청에서 사용한다고 주장하지 않는다.
- 라이브러리의 `quotes()`로 배열 길이를 검사한다. 이 메서드는 수정종가 null을 0으로 바꾸므로, 실제 금융 변환에는 원래 구조화 응답의 null을 보존한다. 누락된 수정종가는 기존 원종가 사용 정책을 유지하고 명시적 0·음수·보정 결과 범위 초과는 거부한다.
- 거래소 IANA 시간대·과거 DST, `adjclose / close` 비율을 OHLC에 한 번 적용하는 방식, 원통화 저장 및 환율 방향/과거값 선택을 유지한다. 배당·분할 이벤트를 가격 보정 위에 다시 더하지 않는다.
- MySQL 스키마와 DB 볼륨은 유지했다. 이번 변경에 프론트엔드 소스 수정은 없다.

새 회귀는 런던/뉴욕 서머타임, 서울·도쿄 자정, 암호화폐 주말, 윤일 요청 경계, 분할·배당의 중복 보정 방지, 수정종가 누락과 0의 구별, null OHLC·배열 불일치, 잘못된 시간대, 보정 수치 범위 초과, KRW/JPY/EUR 환율 방향과 미래 환율 사용 거부를 포함한다.

수정 원화 주가 65,000원, 진입 환율 1,300원/USD, 원금 $1,000이면 20개 보정 단위를 보유한다. 종료 환율이 2,600원/USD이면 최종액은 독립 원장상 **$500**, 수익률은 **−50%**다. 라이브러리 응답→가격 변환→실제 엔진의 결과를 이 값으로 검증했다. 이 테스트는 보정 단위의 Buy & Hold 검증이며 실제 정수 주식 거래 단위 문제(S01)의 해결을 의미하지 않는다.

실제 원본 응답은 `backtest_be_rust/tests/fixtures/yahoo-chart-regression.json`에 고정했다. 기대값은 원본 Python 백테스트를 사용하지 않고 Python 표준 라이브러리 `zoneinfo`와 독립 산술로 생성했다. 같은 응답에 대한 가격 허용 오차는 `1e-12 × max(1, |expected|)`, 날짜·통화·행 수는 정확히 일치해야 한다.

실시간 비교는 서로 다른 Yahoo HTTP 응답을 비교한다. Yahoo가 같은 과거 구간에도 float32 정밀도 수준의 수정종가 차이를 반환하는 것을 관찰하여 상대 오차 `1e-6`을 실조회 허용값으로 명시했다. 최종 새 버전의 최대 관측 상대 차이는 약 `7.17e-7`이었다. 이 느슨한 실조회 기준을 고정 응답 회귀의 엄격한 기준으로 대체하지 않았다. 환율과 BTC 비교 차이는 0이었다.

DB 테스트 묶음을 처음 병렬 실행했을 때 공유 임시 DB의 초기 INSERT 사이에 교착이 발생했다. 테스트 묶음을 `--test-threads=1`로 실행해 3개 모두 통과했으며, 동시성 테스트 자체의 네 읽기 작업·한 쓰기 작업은 그대로 병렬 실행했다. 초기 실패 로그도 보존했다. 이를 모든 운영 캐시 교착이 해결되었다는 근거로 사용하지 않는다.

## 고정 시세 성능·메모리

기존 보존 입력을 그대로 사용했다. 각 API는 CPU 2개·메모리 2GiB, 각 실행은 새 프로세스다. 32종 시나리오를 순서대로 각각 10회 실행하고 추가로 동시 2/8/16 요청을 보냈다. 구현·실행당 346건, 전후 Python/Rust를 합쳐 **1,384건 전부 HTTP 200**, OOM·swap 사용 0이다.

관측기는 다른 cgroup에서 대상 PID/cgroup을 읽는다. 구간별 관측 최대는 샘플링 하한이고, 아래 최대값은 컨테이너 수명 전체의 커널 `memory.peak`다. 프로세스 RSS와 다른 계측치이며 서로 더하지 않는다.

| 측정 | Python 교체 전 대조군 | Python 교체 후 대조군 | Rust 교체 전 | Rust 교체 후 |
|---|---:|---:|---:|---:|
| 순차 요청 중앙값 | 104.02ms | 99.52ms | 4.01ms | 3.84ms |
| 순차 요청 p95 | 285.75ms | 261.77ms | 7.55ms | 7.68ms |
| 시작 시 컨테이너 메모리 | 167.64MiB | 151.79MiB | 2.48MiB | 3.38MiB |
| 커널 최대 메모리 | 232.33MiB | 216.65MiB | 70.27MiB | 68.56MiB |

이 측정은 고정 시세 로딩·계산·JSON 응답 비용을 포함하고 Yahoo 네트워크·응답 해석과 DB I/O는 제외한다. 변경되지 않은 Python 대조군도 실행 간 차이가 있으므로 Rust 중앙값 감소를 라이브러리 교체의 속도 개선으로 단정하지 않는다. 관측 결과는 계산 경로가 비슷한 성능을 유지한다는 제한적인 근거다.

## Yahoo 실제 수집 경로

별도의 DB 없는 새 런타임 컨테이너에서 AAPL, 삼성전자, 도요타, KRW 환율, SAP, BTC, QQQ를 순차 조회했다. QQQ는 2015~2023년 2,264개 일봉이다. 각 종목 최초 요청과 동일 요청의 메모리 캐시 적중을 한 번씩 측정했다. 관측기는 자체 cgroup을 사용하여 메모리에 포함되지 않는다.

| 측정 | Rust 직접 호출 이전본 | Yahoo 라이브러리 버전 |
|---|---:|---:|
| 최초 조회 중앙값 | 143.34ms | 157.31ms |
| 캐시 적중 중앙값 | 1.16ms | 1.15ms |
| 시작 시 메모리 | 2.18MiB | 3.27MiB |
| 커널 최대 메모리 | 9.31MiB | 11.11MiB |
| 성공한 종목/시계열 | 7/7 | 7/7 |

이 짧은 실조회에서는 최대 메모리가 약 1.80MiB 증가했다. 시간에는 Yahoo 서버·네트워크·TLS 연결 지연이 포함되며 각 종목 한 번씩의 관찰이므로 143→157ms 차이를 순수 라이브러리 비용이나 통계적으로 확정된 성능 저하라고 해석하지 않는다. 고정 시세 계산 벤치마크와 이 수집 벤치마크는 별도 프로세스·부하이므로 최대 메모리도 서로 다른 값이다.

## 한계와 재현

[3차 적대적 평가](rust-third-adversarial-audit-2026-11-11.md)의 S01~S06은 여전히 별도 미해결 문제다. 이번 검증은 수집기 변경과 날짜·보정·환율의 회귀를 확인하며, 전체 금융 계산의 무결성이나 원시 기업행사·실거래 정수 주수 재구성을 보증하지 않는다. 전체 브라우저 E2E, 실제 네이버/Turnstile 인증 호출, ARM64, 장기간 메모리 누수는 이번에 재검증하지 않았다.

원시 기록은 `.comparison/reports/yahoo-client-2026-11-11/`, 고정 시세 전후 측정은 `.comparison/reports/yahoo-before-memory-2026-11-11/`와 `yahoo-after-memory-2026-11-11/`에 있다. source-manifest, 빌드·감사·DB 로그, 실조회 JSON, HTTP 결과를 보존했다.

```powershell
docker build --target test ./backtest_be_rust
docker build --target audit ./backtest_be_rust
docker build --target runtime ./backtest_be_rust
# 기존 보고서를 덮어쓰지 않도록 새 이름 사용
./scripts/benchmark-frozen-memory.ps1 -OutputDirectory yahoo-memory-rerun
```

DB 테스트는 `compose.rust-test.yaml`의 임시 MySQL만 대상으로 `RUST_TEST_DATABASE=1` 및 해당 `DATABASE_*`를 주고 `cargo test --locked -- --ignored --test-threads=1 --nocapture`로 실행한다. 제공업체 실조회는 `comparison/verify-yahoo-client.py`, 고정 원본 기대값 생성 절차는 `comparison/capture-yahoo-regression.py`에 있다. 고정 회귀 자료는 자동 재생성하지 않는다.

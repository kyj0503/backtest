# 계산과 참고 데이터의 경계

2026-10-25. 계산과 뉴스·차트 자료가 같은 HTTP 요청에 묶여, 이미 끝난 계산도
외부 조회를 기다리고 참고 자료를 재시도할 때 계산까지 반복하던 문제를 분리했다.
새 DB·큐·서버는 추가하지 않는다.

| API | 책임 | 한도 |
|---|---|---|
| `POST /api/v1/backtest` | 주가 로드와 시뮬레이션, 수익률·거래·자산 곡선 | 기존 컨테이너 전체 8건, IP별 2건, 대기 30초 + 실행 60초 |
| `GET /api/v1/market-data` | 참고 주가·종목 정보·환율·벤치마크·뉴스 | 별도 전체 2건, IP별 1건, 대기 2초 + 실행 20초 |

조회 한도는 `MAX_CONCURRENT_MARKET_DATA`, `MARKET_DATA_QUEUE_TIMEOUT_SECONDS`,
`MARKET_DATA_TIMEOUT_SECONDS`로 조정한다. 수집 자체의 기본 시간 예산은 15초다.
두 실행기는 같은 취소·파일 슬롯 구현을 재사용하지만 슬롯 경로와 계측은 분리한다.
느린 조회는 계산 슬롯을 점유하지 않는다. 시간 초과·연결 종료 후에도 실제 스레드가
끝나기 전에는 슬롯을 반환하지 않는다.

## 요청과 호환성

계산 POST의 본문·응답 필드는 유지한다. 다섯 `include_*` 기본값도 기존처럼 true다.
콘솔은 이를 모두 false로 보내며 이 경우 참고 메타데이터 조회도 건너뛴다.
결과의 참고 자료 필드는 비우고 `supplemental_status`를 skipped로 반환한다.

```text
GET /api/v1/market-data?symbols=AAPL&symbols=MSFT&start_date=2023-01-01&end_date=2023-06-30
```

심볼은 주식 입력과 같은 형식으로 검사·대문자화하고 중복을 제거한다. 입력은 최대
20개, 기간은 최대 3,650일이며 잘못된 날짜·미래 종료일을 외부 I/O 전에 거부한다.
`symbols`를 생략하면 환율·지수 등 공통 자료만 조회할 수 있다.
기존 `include_news`, `include_stock_data`, `include_volatility_events`,
`include_exchange_rates`, `include_benchmarks`를 쿼리 옵션으로 사용할 수 있다.

조회 응답은 `{status: "success", data: {...}}`이며 기존 참고 자료 필드와
섹션별 수집 상태, `sp500_total_return_pct`(자료 부족 시 null)를 제공한다.
이 응답에는 시뮬레이션의 투자금·최종 평가금·거래·자산 곡선을 넣지 않는다.

콘솔은 먼저 계산을 표시하고 참고 자료를 나중에 병합한다. 조회 장애 시 계산 결과를
유지하고 조회만 재시도한다. 새 실행·화면 이탈은 이전 계산/조회 HTTP 요청을 취소한다.
오래된 응답이 새 결과를 덮어쓰지 않으며 참고 응답은 계산 필드를 덮어쓸 수 없다.

## 배포와 검증

백엔드를 먼저 배포하고 새 GET이 정상임을 확인한 다음 콘솔을 배포한다.
두 프록시 진입점 모두 `/api/v1/`를 전달해야 한다. 콘솔 프록시와 외부 공통
게이트웨이의 읽기 제한은 앱의 최대 대기·실행 시간보다 길어야 한다.

기존 API 스냅샷은 새 GET 경로만 별도 허용하고 이전 경로·본문·응답 정의는 계속
동일하게 검사한다. 회귀 검증은 잘못된 조회의 I/O 차단, 계산에서 참고 조회 생략,
조회 슬롯 포화, 느린 조회 중 계산 표시, 조회만 재시도, 오래된 응답 차단,
화면 이탈 취소를 포함한다.

2026-10-25 로컬 검증에서 Docker 테스트 512개와 골든 E2E 1개가 통과했다.
별도로 배포용 BE·콘솔 이미지와 격리 MySQL을 실행했다. 운영 자격증명 없이 합성
시세를 넣어 기존 POST와 분리 API의 계산값이 동일함을 확인했다. 브라우저에서
GET만 503으로 실패시켰을 때 계산 결과를 유지했고, GET 복구 후 참고 자료만
재시도해 차트를 채웠다. 재시도 전후 계산 POST 누적 호출 수는 5건으로 같았다.
이는 기능 검증이며 운영 데이터의 정확성이나 부하 처리 성능을 보장하는 수치는 아니다.

## 남은 경계

작업은 여전히 HTTP 연결에 묶인 동기 응답이다. 브라우저를 닫거나 배포·서버 재시작 시
작업을 복구하지 않으며 결과 보관·작업 ID·대기열 내구성은 제공하지 않는다.
현재 짧은 개인 프로젝트 작업에는 이 구성을 유지한다. 장시간 계산·결과 보관이
필요해지면 그 요구를 근거로 영속 작업 API와 별도 실행 프로세스를 도입한다.
